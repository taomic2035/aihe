# F001 Phase D Implementation Plan — 语音/多端/自进化

**Feature:** F001 — `docs/features/F001-her-companion-ai.md`
**Goal:** 补齐 Her 沉浸感与成长感：语音 <800ms + WatchOS thin + MCP 助理 + GEPA 自进化 + 合规
**Acceptance Criteria:**
- AC-D1: 语音链路 e2e p50 <800ms（级联），支持打断与情感语调，移动端可语音对话（录屏）
- AC-D2: WatchOS thin client 可接收推送、发送文本、同步历史，离线补偿
- AC-D3: 至少 3 个 MCP 助理工具可用（日历/搜索/备忘录），主动关怀可开关
- AC-D4: GEPA 自进化跑通 1 轮：合成+真实 session 评估，产出 PR 且通过门闸并人审合并
- AC-D5: 合规关口全量：AI 披露、自伤检测、危机路由、健康提醒 e2e
**Architecture:** 基于 Phase C 基座叠加：Pipecat/LiveKit WebRTC + Deepgram mock / Fish Audio mock + WatchOS API + MCP Tool Registry + Evolution Plane (DSPy+GEPA skeleton) + Safety Layer
**Tech Stack:** Python/FastAPI, Pipecat, LiveKit, Deepgram SDK (mock), Fish Audio (mock), SwiftUI (WatchOS thin spec), MCP, Langfuse
**前端验证:** Yes — 语音录屏 + WatchOS 真机/模拟 + 合规 e2e

## Straight-Line Check

**Finish line B:** 用户可在手机按住说话→她带情感声音回复且可被打断；手表可收推送/回文本/同步历史；她会用工具查日历/搜索/记备忘并按节律主动问候（可关）；每周 GEPA 进化产出可审计 PR；自伤话术必拦截并给危机资源
**Terminal schema:**
```python
POST /v1/voice/stt  -> text
POST /v1/voice/tts  -> audio bytes
POST /v1/voice/session -> {room, token} (LiveKit)
GET /v1/watch/sync?user_id=&since_version -> {messages, version}
POST /v1/watch/push -> {ok}
POST /v1/tools/call -> {tool, result}
POST /v1/evolution/run -> {pr_url, score}
GET /v1/safety/check?text= -> {risk, action}
```
**Not building:** 端侧真实 ASR/TTS 模型、真实 WatchOS 二进制、真实 GEPA 训练
